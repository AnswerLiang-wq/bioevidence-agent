## 一、120 秒目标主稿（五节拍）

### 节拍 A｜动机与问题定义（目标 20 秒）

我做的是一个可溯源的生物医学证据工作流，并在公开的 PubMedQA 闭合语料上比较 Agent 策略与规则基线。我关注两个问题：表现差多少，以及差别能否归因到具体机制。

### 节拍 B｜设计链（目标 30 秒）

三轮各取 50 例，互不重叠。v1 建立参照；v2 加入同模型、同索引、top-4 固定上下文的单次请求臂，比较整体策略；v3 只澄清 `mixed` 的适用条件。v3 预声明双条件：macro-F1 增量至少 0.04，且 C 在 gold=maybe 上正确率高于 A。

### 节拍 C｜结果（目标 30 秒）

每轮 Agent 的 macro-F1 都高于本轮规则基线，但 v1 实际覆盖 A 49 例（1例 `errored` 按 legacy 口径排除）、规则 50 例；三轮样本不同，v3 又换了评分，所以不能合并。v3 的 maybe 正确数是 C 2/5、A 1/5，但 macro-F1 增量约 0.0374，未达到 0.04，联合判据未满足。

### 节拍 D｜局限与完整性（目标 20 秒）

这是单模型、每轮 50 例的一次运行，未报告置信区间。A/B 证据输入不同，未隔离工具循环。五例诊断由单一 LLM 读者经监督修订，其中 TEST-0487 存在监督分歧，置信度低；用户试点也没有可评估任务。

### 节拍 E｜判断力边界（目标 20 秒）

我保留这些边界，不因结果接近就改阈值。H3 在本轮未达到探索性工程标准；后续更大样本或新的对照仅是候选方案。作品集呈现的是实验设计、记录审计和停止决策，尚未验证普遍性能或用户价值。

## 二、六个追问与回应

### 追问一："三轮都优于规则基线，你的结论是什么？"

三轮的样本不同，评分政策也不同。legacy 政策下 `mixed` 不匹配任何 gold、失败案例不进 macro-F1；v3 政策下 `mixed` 映射为 maybe、全部 50 个已尝试案例进分母、失败案例只给自己的 gold 类加一个 FN。v1 两臂使用同一计划样本，但 macro-F1 实际覆盖 A 49 例、规则 50 例。所以这三组数字不是同一条件下的重复验证，我不能合并成"一致优势"。能说的是：**各轮分别看**，Agent 臂的描述性结果高于同轮规则基线。这个发现是描述性的，不是统计验证。

（来源：O-01／O-02、D-12～D-14、§七评分口径）

### 追问二："0.037 和 0.04 差这么一点，H3 有效还是无效？"

这问的是判断，不是数字。预声明标准的意义是在看到结果之前固定解释规则，所以 0.037 < 0.04 的结论是 `criteria_met = false`，不是"接近通过"。方向确实一致：C 在 maybe 上 2/5，A 是 1/5，第二个条件成立。但支撑集只有 5 例，没有置信区间，也没有显著性检验。我的表述是：H3 作为工程假设值得继续探索，**这一次运行不足以建立一般有效性**。更大样本或跨模型重复**只能写成候选方案**——本轮没有执行，也不承诺它必然解决归因问题。

（来源：D-02～D-05、D-08、P-01）

### 追问三："你怎么控制 loop 的贡献？"

这正是 v2 加固定上下文臂的原因。v2 的结果是 A 0.6003、B 0.5388。但要诚实说清这个比较**不能**隔离循环：A 和 B 的证据输入、提示结构和调用方式都不同。协议里也明文把能主张的范围限定为"整体策略差异，含证据选择"，不能归因于循环本身。所以我能说的只是：**存在策略层面的差别，机制未知**。

（来源：D-13、O-03、O-08、P-01）

### 追问四："你这些实验的检索条件是什么？"

**v2 和 v3 的协议声明了** BM25 title-assisted，即索引文档含标题；**v1 自己的运行记录没有记录检索条件**，现有归档里只有后续协议的追溯声明，我把它标为未确认，没有用当前代码去补。另外，仓库里还有一条独立的旧检索基准链路，包含 RRF 融合和 cross-encoder 重排——那是**另一个实验**，不能替代三轮 Agent 的检索记录。旧检索基准的 title-assisted 条件是有利的源定位条件：问题和标题高度重合，四个检索器在该条件下的检索指标均为 1.000；这不是三轮 API 答题表现。

（来源：§八检索条件表；experiment_log §2.1）

### 追问五："验收标准没达到，下一步怎么办？"

分两层。工程层：H3 方向一致但单次证据不足，候选方案是更大样本或不同模型重复，以及对 maybe 错误做更细的分类。已有的五例诊断里，固定分类是 **2 例条件依赖（0146／0260）、2 例单向（0150／0248）、1 例混合结构（0487）**。这个诊断只做描述，不映射答案，也没有"规则无法修复"这种判定。产品层：`criteria_met = false` 是工程决策结论，不是产品发布结论。产品的价值设计目标是让人审查可溯源的证据，而不是替代判断；但**这个价值没有被验证**——试点 0 个可评估任务，没有用户价值、节时或信任数据。如果问我会不会调低阈值：不会，事后调整让预声明失去意义。

（来源：诊断归档 §3；P-01～P-07；试点状态）

### 追问六："你怎么看自己项目的局限？"

四类，都写进文档了。第一，公开闭集、标签公开，不是盲测，不代表真实世界表现。第二，每轮单次 50 例，没有置信区间、没有跨模型验证；`deepseek-flash` 是实验模型，结论不能推广。第三，环境快照有缺口：三轮都没记录 Python 版本和依赖版本；**v1 全系列的提示词指纹现有归档未提供**。这里要精确：v2 是**两份原始分段有指纹、合并报告没有**；v3 分段与合并都有。合并字段遗漏不等于原运行没有记录。第四，一次形成性试点 0 个可评估任务，没有用户价值证据。

（来源：W-05、G-01／G-02、D-01、experiment_log §2.2）

## 三、补充准备

### 3.1 逐类 F1 的不对称（v3）

| 类别 | A | C |
|---|---:|---:|
| yes | 0.7547 | 0.7843 |
| no | 0.8125 | 0.7879 |
| maybe | 0.1429 | 0.2500 |

本轮 maybe 的 F1 低于 yes／no，maybe 支撑集为 5 例。同时误转统计是：**yes→maybe 两臂都是 6；no→maybe A 是 2、C 是 3**。注意 6+2=8、6+3=9 是**合计误转数**，不是 yes 类的数字。这组数**不能**用来证明模型"在哪类结构上倾向于 supported"，那属于未验证的机制解释。可把这种逐类差异作为后续设计的线索，但不据此确认 H3 或指定其原因。

（来源：D-06、D-07、O-04、O-07）

### 3.2 成本（一律是估算）

- 三轮全部是 `deepseek-flash` 的 API 估算，**不是账单**；估算按记录的峰值 cache-miss 费率计算。设计者／编码助手的模型**不是**实验模型。
- 已知小计：v1 \$0.18653、v2 \$0.240517、v3 \$0.439377，合计 **\$0.866424**。
- **这个合计不能称为完整费用**：v1 有一例用量未完整记录（`PUBMEDQA-TEST-0402`，`cost_complete = false`）。部分用量下，已知小计对整轮实际账单的**界限方向未知**——不插补、不当零。
- v2 有一处**显示舍入**差异：逐例未舍入合计 0.2405172，报告总额 0.240517，而两臂展示值相加是 0.240518。引用时**不要**写 `0.196013 + 0.044505 = 0.240517`，那个等式不成立。

（来源：D-21、D-22、D-26、D-27、experiment_log §1.3）

### 3.3 诊断材料的固定表述

- 方法：**单一 LLM 读者、经监督反馈修订；未测量独立标注者一致性。**
- 监督者事先已知 v3 结果，**不构成**第二名独立盲读者。
- **不报告读者准确率**：没有预声明的读者答案评测臂，不做读者与模型的正确率比较。
- **不存在**结构分类到 verdict 或答案的自动映射。
- **TEST-0487 的「混合结构」分类有未消解的监督分歧，置信度低**，不用于确证任何假设，也不用于推断任一臂的条件识别能力。

（来源：诊断归档 §2、§5；W-01、W-02、P-04）

### 3.4 一句话边界

三轮实验**没有**证明：跨轮普遍优势、循环的单独贡献、读者准确率、H3 已确认、用户价值或效率提升。这些都不是"降级表述"，而是**没有来源支撑**，因此不写。

（来源：W 类全部；P 类全部）
